## DECISION ARCHITECTURE

src/decision/:
  types.ts, DecisionEngine.ts, DecisionPolicy.ts, DecisionValidator.ts,
  DecisionExplanation.ts, DecisionAuditLog.ts, ContradictionDetector.ts,
  DecisionSimulator.ts, index.ts

Pipeline:
  LLM outcome + conversation refs + memory hints + environment
  → DecisionEngine.evaluate → Decision
  → JarvisRuntime routes ANSWER / CLARIFICATION / ACTION / …
  → ACTION still goes through ActionPlanner → Permission → Confirmation → Executor

## CONFIDENCE

0..1 with categories VERY_LOW..VERY_HIGH.
ACTION_MIN_CONFIDENCE = 0.72 (configurable via DecisionPolicy).
LOW / VERY_LOW never auto-become ACTION.

## CONTRADICTIONS

ContradictionDetector:
- user_correction ("non, Chrome")
- memory_vs_explicit (explicit wins)
- keep_open_vs_close → NO_ACTION

## CONTEXT USAGE

Environment / ContextSnapshot remain informational.
contextUsed flag on Decision; multi-app ambiguity → CLARIFICATION.

## MEMORY USAGE

shouldConsultMemory() relevance helper.
memoryUsed flag; memory preference never overrides explicit user request.

## ACTION GATING

DecisionPolicy.canProposeAction:
- USER_REQUESTED only
- confidence threshold
- no missing fields
- no clarification pending
CONTEXT_SUGGESTED never becomes ACTION.
DecisionValidator rejects forbidden payload fields (confirmationGranted, shell, …).

## CLARIFICATION

Minimal questions ("Safari ou Chrome ?", "Quelle application ?").
INFORMATION_REQUIRED when target missing / unresolved reference.

## SECURITY

No ActionExecutor / PermissionManager / ActionConfirmation imports in src/decision.
Injection → NO_ACTION / REFUSAL.
Fake confirmation fields rejected.
Security level may appear in evidence only — never bypasses Phase 8.

Sophie: no BehaviorBrain changes; no new typed Sophie command events
(decision audit is JARVIS-side). High-level Sophie decision signals deferred
to avoid integration-contract churn.
