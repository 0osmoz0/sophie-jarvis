1. ARCHITECTURE
---------------
USER → JarvisRuntime → IntentRouter → LLM → Validator
  ├─ ACTION INTENT → ActionPlanner → Risk/Permission → Confirmation → Executor
  └─ CONTEXT INTENT → ContextService → ContextSnapshot → ResponseFormatter
→ USER

Principle: context informs; context never decides.
LLM interprets; Runtime orchestrates; Brain/Policy retains action authority.

3. DATA AVAILABLE (when services configured)
--------------------------------------------
system: OS / arch / CPU / memory / uptime via ObservationService
applications: running + active via ApplicationService (honest filter running===true)
screen: displays / window metadata / activeWindow via ScreenService
activity / presence: aggregate idle via UserActivityService
files: configured paths + entry count metadata via ObservationService

4. DATA UNAVAILABLE / UNKNOWN (honest)
--------------------------------------
Without ApplicationService → applications.status = unavailable
Without ScreenService → screen.status = unavailable
Without UserActivityService → activity/presence = unknown
permission_required / error when backends report them
Never invents apps, windows, presence, battery, key content
