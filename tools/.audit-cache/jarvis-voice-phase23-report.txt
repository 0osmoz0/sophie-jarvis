   quand processInput s’exécute; MemoryService inchangé (pas d’auto-mémoire vocale)
10. Confirmations vocales? Exactement Phase 8 ActionConfirmation token via
    processInput("oui") — jamais mot « oui » seul / confiance STT / contexte vocal
11. Erreurs STT? Taxonomie VOICE_STT_* / PERMISSION_REQUIRED / EMPTY / LOW_CONFIDENCE;
    low confidence → clarification, aucun processInput
12. Erreurs TTS? Fallback texte; VOICE_TTS_* jamais promu en erreur d’action
13. ConversationService? Via processInput normal (append user/assistant)
14. MemoryService? Aucune promotion automatique Voice→Memory; MemoryPolicy décide
15. Ollama? Indirect — même IntentRouter/LLM path qu’une entrée texte
16. Nouveaux risques? Injection via transcript (mitigé par pipeline);
    fausse confiance STT (bloquée sous seuil); confusion confirmation (token);
    fuite audio (mitigée: pas de stockage); TCC bypass (interdit, messages honnêtes)
17. Limitations? Pas de STT/TTS OS natif; pas de wake word; pas de micro réel;
    push-to-talk explicite seulement; latence micro réelle indisponible
18. Phase 24 nécessaires? Bridge natif SFSpeechRecognizer + AVSpeechSynthesizer;
    permission TCC réelle; interruption barge-in OS; (wake word seulement si
    infra propre) — Phase 24 NOT STARTED
